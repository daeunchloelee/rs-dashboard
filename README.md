# 새내기주 트래커

최근 1년 6개월간 코스피·코스닥 신규상장 종목의 공모가 대비 수익률과 최근 공시를 추적하는 정적 대시보드입니다.
GitHub Pages로 호스팅되고, GitHub Actions가 평일 장 마감 후 하루 한 번 네이버 증권 종가를 가져와 자동으로 갱신합니다.
관심 있는 종목은 표의 별표(★)를 눌러 관심종목으로 표시할 수 있고, 이 설정은 브라우저(localStorage)에만 저장됩니다.
종목 행을 클릭하면 상장 당시 가이던스(추정치) 대비 실제 실적을 볼 수 있는 패널이 펼쳐집니다 — 가이던스는 직접 입력하고, 실제 실적은 DART Open API에서 자동으로 가져옵니다.

## 폴더 구조

```
.
├── index.html                       대시보드 (GitHub Pages가 그대로 서빙)
├── data/
│   ├── companies.json               종목 목록 · 상장일 · 공모가 · 시초가 수익률 (고정 데이터)
│   ├── prices.json                  현재가 (GitHub Actions가 자동 갱신 — 처음엔 비어있음)
│   ├── disclosures.json             주요 공시 하이라이트 (수동 갱신 스냅샷)
│   ├── actuals.json                 실제 실적 (GitHub Actions가 DART에서 자동 갱신 — 초기 스냅샷 포함)
│   └── corp_codes.json              종목코드 → DART corp_code 매핑 캐시 (최초 실행 시 자동 생성)
├── scripts/
│   ├── fetch_prices.py              네이버 증권 시세를 가져와 prices.json을 쓰는 스크립트
│   └── fetch_actuals.py             DART Open API에서 실제 실적을 가져와 actuals.json을 쓰는 스크립트
└── .github/workflows/
    ├── update-prices.yml            스케줄러 (평일 16:00 KST, 하루 1회)
    └── update-actuals.yml           수동 실행 전용 (분기·반기보고서가 새로 나왔을 때 직접 실행)
```

가이던스(상장 당시 추정치)는 더 이상 이 저장소에 파일로 들어있지 않습니다 — 페이지에서 종목을 클릭해 직접 입력하면 그 브라우저에만 저장됩니다. 자세한 내용은 아래 "가이던스(추정치) 입력" 항목을 참고하세요.

## 처음 올릴 때 해야 할 4가지

1. **새 저장소 만들기**
   GitHub에서 새 저장소를 만듭니다 (예: `ipo-tracker`). GitHub Pages를 무료로 쓰려면 **Public**으로 만드는 게 가장 간단합니다.
   이 폴더 전체를 그 저장소에 업로드합니다 (`git init && git add . && git commit -m "init" && git remote add origin <repo주소> && git push -u origin main`, 또는 GitHub 웹의 "Add file → Upload files"로 드래그 앤 드롭해도 됩니다).

2. **Actions에 쓰기 권한 주기**
   저장소 **Settings → Actions → General → Workflow permissions**로 이동해 **"Read and write permissions"** 를 선택하고 저장합니다.
   (이걸 안 하면 봇이 `prices.json`을 커밋하지 못하고 워크플로가 실패합니다.)

3. **GitHub Pages 켜기**
   저장소 **Settings → Pages** 로 이동해 **Source: Deploy from a branch**, **Branch: main / (root)** 로 설정하고 저장합니다.
   1~2분 후 `https://<사용자명>.github.io/<저장소명>/` 주소가 생깁니다.

4. **최초 1회 수동 실행**
   저장소 **Actions** 탭 → 왼쪽에서 **"종가 자동 갱신"** 워크플로 선택 → **Run workflow** 버튼 클릭.
   1분 이내로 끝나고, `data/prices.json`이 채워진 커밋이 자동으로 생깁니다. 이후 페이지를 새로고침하면 값이 보입니다.

그 다음부터는 평일 장 마감 후(16:00 KST) 하루 한 번 자동으로 갱신됩니다. 별도로 할 일은 없습니다.

(실제 실적(DART) 자동 갱신은 별도 설정이 필요합니다 — 아래 "실제 실적 자동 갱신 (DART)" 항목을 참고하세요. `data/actuals.json`에는 이미 초기 스냅샷이 채워져 있어 당장 설정하지 않아도 페이지는 정상 동작합니다.)

## "종가 기준" 추적의 의미와 한계

- 이 트래커는 분·시간 단위 장중 시세가 아니라 **하루 한 번, 장 마감 후 종가**만 추적합니다. 그래서 장중에 페이지를 열어도 전날 종가가 그대로 보이는 게 정상입니다.
- **GitHub Actions가 평일 16:00 KST에 한 번** 네이버 증권의 공개(비공식) 시세를 가져와 저장소에 커밋하는 방식입니다.
- 네이버 증권 API는 **공식 문서가 없는 비공식 API**입니다. 언제든 응답 형식이 바뀌거나 일시적으로 막힐 수 있으며, 그런 경우 `fetch_prices.py`는 실패한 종목만 건너뛰고 나머지는 정상 처리합니다. 페이지에서도 조회에 실패한 종목은 "스냅샷" 배지로 표시되고 리포트 발행 시점 수익률을 대신 보여줍니다.
- 종목코드가 `0009K0`처럼 영숫자로 된 최근 신규상장 종목은 네이버 배치 조회 API가 지원하지 않을 수 있어, 개별 상세 API로 재시도합니다. 그래도 안 되면 스냅샷 값을 유지합니다.
- 주말·공휴일에는 직전 거래일 종가가 그대로 보입니다.

## 갱신 주기를 바꾸고 싶다면

`.github/workflows/update-prices.yml`의 `cron` 값을 수정하면 됩니다. 예:

- 아침에 전일 종가로(장 시작 전, 08:30 KST = 23:30 UTC 전날): `30 23 * * 0-4`
- 하루 2번(마감 직후 + 아침): 두 개의 cron 줄을 추가하면 됩니다.
- 다시 장중 여러 번으로 되돌리려면: `*/20 0-6 * * 1-5` (20분 간격, 09:00~15:40 KST)

cron은 UTC 기준이고, 한국시간(KST)은 UTC+9입니다.

## 관심종목(★)

표 맨 왼쪽의 별표를 클릭하면 관심종목으로 표시/해제됩니다. 정렬 드롭다운에서 "관심종목 우선"을 고르거나, "★ 관심종목만" 체크박스로 필터링할 수 있습니다. 이 설정은 서버나 저장소가 아니라 **보고 있는 브라우저의 localStorage에만** 저장되므로, 다른 기기·브라우저·시크릿 모드에서는 보이지 않고 브라우저 저장공간을 지우면 함께 사라집니다.

## 집계 기간(1년 6개월 롤링 윈도우)

`index.html`의 `TRACK_MONTHS` 상수(기본값 18)를 기준으로, 페이지를 열 때마다 "오늘 - 18개월" 이후에 상장한 종목만 트래커 표·차트·통계에 표시됩니다. 날짜를 고정해두지 않았기 때문에 별도 수정 없이 시간이 지나도 자동으로 기간이 밀립니다. (가이던스 입력·실적 조회는 종목 단위 기능이라 이 기간과 무관하게 동작합니다.)

## 가이던스(추정치) 입력

기술특례상장 종목은 증권신고서의 "인수인의 의견"(투자설명서)에 향후 몇 년치 추정 매출액·영업이익·당기순이익을 공개해야 합니다. 다만 이 원문 문서는 DART API로 제공되지 않아(공시 메타데이터·재무제표 실적치만 API로 조회 가능) 자동으로 가져올 수 없습니다 — 그래서 이 값은 직접 입력하는 방식으로 만들었습니다.

- 표에서 종목 행을 클릭하면 패널이 펼쳐집니다. 아직 입력한 가이던스가 없으면 연도별 입력 폼이 바로 나오고, 매출액·영업이익·당기순이익(억원)만 입력하면 됩니다 — 실제 실적은 자동으로 옆에 붙으므로 따로 입력할 필요가 없습니다.
- 입력값은 **이 브라우저의 localStorage에만** 저장됩니다. 서버나 저장소 파일에는 반영되지 않으므로 다른 기기·브라우저·시크릿 모드에서는 보이지 않고, 브라우저 저장공간을 지우면 함께 사라집니다.
- 표 위의 "내가 입력한 가이던스 내보내기" 버튼을 누르면 지금까지 입력한 내용을 JSON으로 볼 수 있습니다. 이 내용을 Claude에게 전달하면 `data/guidance_seed.json` 같은 파일로 저장소에 영구 반영하도록 도와드릴 수 있습니다 (원하시면 언제든 요청해주세요 — 자동으로 반영되지는 않습니다).

## 실제 실적 자동 갱신 (DART)

`data/actuals.json`에는 전년도까지는 사업보고서(연간) 기준, 올해는 공시된 가장 최근 분기·반기보고서(누적) 기준의 실제 매출액·영업이익·당기순이익이 들어있습니다. 이 저장소에는 처음 만들어질 때의 스냅샷이 이미 채워져 있어 바로 쓸 수 있지만, 새 분기·반기보고서가 나오면 다음과 같이 직접 갱신해야 합니다(예약 실행 없음 — 수동 전용).

1. **DART Open API 키 발급**: [opendart.fss.or.kr](https://opendart.fss.or.kr) 에서 무료로 회원가입 후 API 인증키를 발급받습니다.
2. **저장소에 시크릿 등록**: 저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서 이름 `DART_API_KEY`, 값에 발급받은 키를 입력해 저장합니다.
3. **필요할 때마다 수동 실행**: 저장소 **Actions** 탭 → 왼쪽에서 **"실제 실적 자동 갱신"** 워크플로 선택 → **Run workflow** 버튼 클릭. 완료되면 `data/actuals.json`(및 `data/corp_codes.json` 캐시)이 갱신된 커밋이 자동으로 생깁니다.

몇 분마다 자동으로 돌 필요는 없으므로 스케줄(cron)은 없습니다 — 분기보고서(5월·11월경)·반기보고서(8월경)·사업보고서(3월경)가 새로 나오는 시기에 맞춰 눌러서 실행해주세요. `corp_codes.json`은 종목코드→DART corp_code 매핑을 캐시해두는 파일이라 평소엔 다시 안 만들어지며, 새 상장 종목이 매핑에 안 잡힐 때만 이 파일을 지우고 다시 실행하면 최신 매핑을 다시 받아옵니다.

## 종목 목록을 추가/수정하고 싶다면

`data/companies.json`을 직접 편집하면 됩니다. 각 항목의 필드는 다음과 같습니다.

| 필드 | 설명 |
|---|---|
| `name` | 종목명 |
| `ticker` | 종목코드 (모르면 빈 문자열 `""`) |
| `market` | `"코스피"` 또는 `"코스닥"` |
| `listDate` | 상장일 `YYYY-MM-DD` |
| `ipoPrice` | 공모가(원), 모르면 `null` |
| `day1Pct` | 상장 첫날 시초가 수익률(%), 모르면 `null` |
| `snapshotPct` / `snapshotDate` | 종가 조회가 안 될 때 대신 보여줄 리포트 스냅샷 수익률과 그 기준일 |
| `spac` | 스팩/리츠 등이면 `true` |
| `note` | 표에 ⓘ 아이콘으로 뜨는 참고 메모 |

`ticker`를 채워 넣은 종목은 다음 자동 갱신 때부터 바로 종가 추적 대상에 포함됩니다.
